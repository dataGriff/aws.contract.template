# Authoring the contract

`api/openapi.yaml` is the only hand-written input. Everything else is generated by `task gen` and
committed (drift-gated by `task gen:check`).

## Conventions (enforced)

- **`lower_snake_case`** for schema names, properties, enum values, query/path parameter names and
  operationIds (`redocly.yaml` custom rules). HTTP header parameters stay kebab-case
  (`idempotency-key`, `x-api-key`).
- Every operation has a unique `operationId` and a 2xx response.
- **No AWS extensions.** The spec must stay portable; the provider renders its own
  `x-amazon-apigateway-*` copy at deploy time.
- **Errors** are the shared `problem` schema (RFC 7807) referenced via `components/responses`.
- **Creates** take `idempotency_key` and declare `links` from the 201 to the by-id operations so
  the provider's stateful conformance tests can follow them.
- **Every status a provider may return must be declared**; the provider's contract layer fails on
  undeclared statuses.
- The `servers` entries are documentation placeholders (`no-server-example.com` is off).

## Workflow

```bash
task spec:lint        # redocly: rules + naming
task gen              # types, zod, client, .http collection, API reference
task test:mock        # the collection must replay cleanly against a mock of the contract
task contract:compat  # breaking-change check vs the base branch (oasdiff)
task ci
```

## Versioning and breaking changes

- The package version is decided by **semantic-release** from conventional commits on `main`
  (`fix:` → patch, `feat:` → minor, `feat!:` / `BREAKING CHANGE:` → major). At release time
  `scripts/set-version.mjs` writes the same version into `info.version`, so the spec a consumer
  resolves from `node_modules` states the version they installed. Never edit either by hand.
- `task contract:compat` runs `oasdiff breaking` against the base branch and **fails** on breaking
  changes (removed/renamed fields or operations, tightened request constraints, dropped responses).
- To ship a breaking change deliberately: make the commit `feat!: …` (or add a `BREAKING CHANGE:`
  footer), and run the gate with `CONTRACT_ALLOW_BREAKING=true` (locally and as a repository
  variable on that PR's CI, or accept the failing check knowingly). The next release is a new
  **major**; consumers opt in by bumping their range.
- The URL base path (`/v1`) is a separate axis: bump it only when you must run two incompatible
  versions side by side.

## Replacing the Todo domain

Use the `author-contract` skill (`.claude/skills/author-contract/`): keep the shared components
(`problem`, pagination, idempotency, security schemes), swap the domain schemas and paths, then
`task gen` and `task ci`. Replacing the contract wholesale is breaking by definition — that first PR
runs with `CONTRACT_ALLOW_BREAKING=true`.
